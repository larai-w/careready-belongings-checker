# 🧳 CareReady — 持ち物準備・帰宅チェック

**ショートステイ、入院、デイサービスなどの準備と、帰宅時の持ち物確認を支援するPWAです。**

[アプリ](https://veai.jp/ready/) · [English](README.md) · [開発への参加](CONTRIBUTING.md)

家族向けの基本チェックリストは登録不要です。行き先に合わせた持ち物を選び、数量、入れ物、準備・帰宅のチェックを端末に保存します。医療判断や臨床効果を提供するものではありません。

## できることと提供範囲

- 行き先・条件に応じた持ち物リストの表示。
- 持ち物や入れ物の追加、数量と箱への割り当て。
- 準備チェックと帰宅時の確認。
- 現在表示している持ち物、数量、箱、保存済みメモの印刷。
- 準備データのJSON保存と、内容確認後の復元。
- 施設コードからのテンプレート取得、写真の文字読み取りなどのオンライン機能。

家族向けWeb MVPは公開中です。施設管理画面や施設の利用開始手順は、家族向けチェックリストとは分けて開発・確認します。施設スタッフのテンプレート編集にはCognito認証を使います。

## 保存と復元の違い

| 操作 | 内容 |
| --- | --- |
| 端末内保存 | `storage.js` を通してIndexedDBへ保存。localStorageの代替経路もあります |
| リスト共有 | 持ち物リストを共有。準備のチェック状態を含むバックアップとは異なります |
| 準備JSONの保存 | 持ち物・入れ物・割り当て・準備と帰宅チェック・条件・予定・施設テンプレートなど |
| 準備JSONの復元 | 確認後に対象の準備状態を置き換えます。自動同期や差分マージではありません |

バックアップ対象外は、日記、写真、本人名、自由メモ、通知設定などです。復元先にあるこれらの値は維持します。戻したくなる可能性がある場合は、置き換え前にも保存してください。

ファイルはCareReady version 1のJSON、最大2MBです。IndexedDBの一つのtransactionで値を確認して復元します。localStorageのみの場合は保存ファイルの出力はできますが、一括復元は受け付けません。

ファイルには持ち物名・予定・施設情報が含まれ得ます。ブラウザーデータを消しても、出力済みファイルや共有先のコピーは消えません。

## ローカル起動

GitとPython 3を用意します。フロントエンドのビルドや依存パッケージのインストールは不要です。

```bash
git clone https://github.com/larai-w/careready-belongings-checker.git
cd careready-belongings-checker
python3 -m http.server 8000 --bind 127.0.0.1
```

**http://localhost:8000/** を開きます。終了は `Ctrl+C` です。`file://` ではなくHTTPで開いてください。

検証専用のブラウザープロフィールで、架空の持ち物を使い、行き先選択→持ち物追加→入れ物への割り当て→帰宅確認→JSON保存・復元確認を試せます。この操作例は、今回実施した使いやすさ評価ではありません。

オフライン利用には、初回の読み込みとキャッシュ作成が必要です。初回から通信なしで利用できるとは限らず、CDNのスタイルやオンライン機能にも依存範囲があります。

## ローカル起動でも本番へ接続する機能があります

`app.js` の `API_URL` は空で、標準リストは同梱の `data.json` を使用します。一方で、別の `API_BASE` は配信中のバックエンドを指しています。

そのため、localhostでも施設コード取得、OCR、通知、フィードバック、管理操作まで自動的に隔離されるわけではありません。通常の開発は基本チェックリスト・印刷・JSON操作に絞り、オンライン機能を試す場合は明示的に隔離された開発APIへ接続してください。実際の情報や画像を検証目的で本番へ送らないでください。

OCRは選択した画像をサーバーへ送る処理です。候補は人が確認して追加します。ブラウザー内だけで行う印刷とは異なります。

## 技術構成と検査

| 層 | 構成 |
| --- | --- |
| 画面 | Vanilla JavaScript、ES Modules、Tailwind CDN |
| 端末保存 | IndexedDB、localStorageフォールバック |
| オフライン | Service Worker |
| API | API Gateway、Python Lambda、DynamoDB |
| 施設認証 | Cognito。管理者による利用者登録 |
| インフラ | Python版AWS CDK |

Node.jsの既存ロジックテストは `npm test` です。バックエンドはpytest/motoを使います。コマンド、依存関係、各検査へのリンクは[英語README](README.md#testing-and-engineering-evidence)に、ブラウザー検査は[開発ガイド](docs/DEVELOPMENT.md)に記載しています。コマンドの掲載は最新実行結果を意味しません。

## 公開・配信

`main` へのpush後、CIの `check` が成功するとフロントエンドを配信します。**文書だけの変更でも配信対象です。** 手動配信とバックエンドのCDK配信も別途あります。

ブランチでの文書レビューと本番へのマージは分けて判断します。READMEを試すためにbootstrapやdeployを実行する必要はありません。

公開ファイルをステージした後は、次のガードを実行します。

```bash
python3 scripts/check_public_repo.py --staged
```
