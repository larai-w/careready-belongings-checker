# 実機 E2E ウォークスルー(M1 安全確認 / Issue #6)

最終更新: 2026-07-28

## 目的

パイロット協力者を招く前に、本番 `https://veai.jp/ready/` の主要フローを**実機で人間が目視完走**し、重大不具合が残っていないことを確認する。これは **M1 安全確認**ゲートであり、自動テスト(`test-e2e.html` / `test-smoke.html`)では代替できない実機・実運用の確認である。

このドキュメントは owner が実行する**手順書兼証跡記録テンプレ**である。記入時は個人情報・健康情報・施設特定情報・認証情報を書かない([PUBLIC_REPOSITORY_POLICY.md](PUBLIC_REPOSITORY_POLICY.md))。

## 事前準備

- 施設側: `https://veai.jp/ready/admin/` を開く実ブラウザ(スマホではなく PC/タブレットのブラウザを推奨)。拡張機能やパスワード自動入力に依存しない、素の状態が望ましい。
- 家族側: `https://veai.jp/ready/` を開く実スマートフォン(iOS Safari / Android Chrome の少なくとも一方、可能なら両方)。
- 認証情報は [16_認証情報ローテーションと復旧runbook.md](16_認証情報ローテーションと復旧runbook.md) の手順でローテーション済みであること(Issue #7)。
- テストデータ方針: このウォークスルーで作成したテンプレは、確認後に削除するか「テスト用」と分かる名称にする。本番の実データと混在させない。氏名・部屋番号などは入力しない(ダミー名で行う)。

## ウォークスルー手順と確認

各行の「確認」に日付と結果(OK / NG)を記入する。NG は末尾の不具合記録表に転記する。

| # | 操作 | 期待結果 | 確認(日付/OK・NG) |
|---|---|---|---|
| 1 | 施設スタッフが実ブラウザで `https://veai.jp/ready/admin/` にサインイン(メールアドレスでログイン) | サインイン成功、施設テンプレ管理画面が表示される | |
| 2 | テンプレートを新規作成(ダミー名・数項目) | 作成成功、shareCode(6文字)/QR が払い出される | |
| 3 | 払い出された QR / コードを控える | QR 表示・コード文字列が確認できる | |
| 4 | 別のスマホ実機で QR / コードからテンプレを取込(redeem) | テンプレ内容がスマホに取り込まれる | |
| 5 | スマホを**オフライン**(機内モード)にして再度開く | 取込済みテンプレがオフラインで保持・表示される | |
| 6 | 準備(持ち物チェック)フロー | 項目のチェック状態が保存され、再表示で保たれる | |
| 7 | 帰宅確認(return check)フロー | 帰宅時の確認フローが完走できる | |
| 8 | 状態トグル(condition toggle)操作 | トグルの切替と保存が反映される | |
| 9 | 印刷(print)パス | 印刷プレビュー/出力が崩れず表示される | |

> 補足: 5 のオフライン保持は Service Worker とローカル保存に依存する。オンラインに戻したときに二重取込や状態消失が起きないかも合わせて見る。

## 不具合記録(PII/PHI・認証情報を書かない)

| ID | 発生手順# | 事象(操作と結果) | 重大度(critical/major/minor) | 状態(open/fixed) | 証跡(スクショ等の保管先・非公開) |
|---|---|---|---|---|---|
| | | | | | |

- 重大度 **critical** の定義: データ消失、別施設データ混入、認証回避、主要フローの完全停止のいずれか。M1 ゲート(判定ゲート2)では critical が0件であること。
- 証跡のスクショに氏名・部屋番号・メール・コード等が写る場合は、このリポジトリではなく非公開の作業領域(`.private/` 等)に保管し、ここにはリンクや所在の要約のみ書く。
