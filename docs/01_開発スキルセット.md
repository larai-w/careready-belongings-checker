# CareReady 開発スキルセット
— Fable(Claude)がこのアプリを開発する場合に使う技術・スキルの整理 —

## 1. 現状のアプリ把握

| 項目 | 現状 |
|---|---|
| 形態 | 単一 `index.html`(SPA未満の1ページアプリ) |
| UI | Tailwind CSS(CDN版) |
| ロジック | Vanilla JavaScript(フレームワークなし) |
| データ取得 | `fetch()` で veai.jp のAPIからJSON取得 |
| 状態保存 | `localStorage`(チェック / 不要 / 箱割り当ての3キー) |
| 機能 | 場所別リスト表示、コンテナ(箱)別ソート、進捗バー、一括リセット |

現状は「動くプロトタイプ」段階。ここから製品化するために必要なスキルを以下に整理する。

## 2. フェーズ別・必要スキルマップ

### Phase 0: プロトタイプ強化(現状の延長)
- **Vanilla JS のリファクタリング** — 描画ロジックと状態管理の分離、XSS対策(`innerHTML` にアイテム名を直接埋めているため、API側データ次第で脆弱)
- **Tailwind CSS** — CDN版から ビルド版(purge済み)への移行
- **REST API 設計** — 現在プレースホルダのままの `API_URL` を確定させ、エラー時のリトライ・オフライン時フォールバックを実装
- **PWA化** — Service Worker + manifest.json。介護現場は電波が弱い場所(施設内・病院内)が多く、**オフライン動作は必須級**

### Phase 1: 製品化(MVP)
- **フロントエンドフレームワーク** — React または Svelte。リスト描画・状態同期が複雑化するため全再描画方式から脱却する
- **TypeScript** — アイテム/場所/コンテナのデータモデルを型で固定
- **バックエンド** — Node.js (Hono/Express) または Cloudflare Workers。veai.jp の既存インフラに合わせる
- **データベース** — SQLite(Turso/D1)か Supabase(PostgreSQL)。「テンプレート(施設側)」と「個人のチェック状態」の2層構造
- **認証** — 家族間共有を実現するなら必須。マジックリンク or LINEログイン(介護世代のユーザー層にはLINEが最適)
- **テスト** — Vitest(単体)+ Playwright(E2E)。チェック状態の永続化まわりは回帰バグが出やすい

### Phase 2: 拡張
- **リアルタイム同期** — 家族複数人で同じリストを編集(Supabase Realtime / WebSocket)
- **プッシュ通知** — 「明日ショートステイです。準備は 12/34 です」(Web Push)
- **AI連携(Claude API)** — 「要介護3・おむつ使用・3泊4日のショートステイ」→ 持ち物リスト自動生成。既存の veai エコシステムとの差別化ポイント
- **印刷/PDF出力** — 施設に紙で渡す文化がまだ強いため、A4チェックリスト出力
- **多言語対応** — 外国人介護スタッフの増加を見据えた i18n

## 3. Fableが実際の開発で使う作業スキル

| スキル | 具体的な使い方 |
|---|---|
| コードリーディング | 既存327行の構造把握、暗黙のデータスキーマ(`locations` / `categories` / `applicable_locations`)の復元 |
| リファクタリング | `renderChecklist()` の全再描画方式 → 差分更新への段階的移行 |
| API設計 | JSONスキーマ定義、OpenAPI仕様書作成 |
| セキュリティレビュー | XSS(innerHTML)、localStorage のデータ検証、CORS設定 |
| テスト設計 | チェック→リセット→再チェックなど状態遷移のE2Eシナリオ作成 |
| UX検討 | 高齢の家族介護者(50〜70代)向けの文字サイズ・タップ領域・コントラスト調整。現状のダークテーマ+シアンは若年層向けで、**メインターゲットと乖離している可能性が高い**(要ユーザーテスト) |
| ドキュメント | README、API仕様、施設向け導入マニュアル |
| インフラ | Cloudflare Pages / Vercel へのデプロイ、独自ドメイン(careready.veai.jp 等)設定 |

## 4. 推奨技術スタック(結論)

```
フロント : Svelte + TypeScript + Tailwind (ビルド版) + PWA
バック   : Cloudflare Workers (Hono) + D1 (SQLite)
認証     : LINEログイン(ターゲット層との親和性)
AI       : Claude API(リスト自動生成)
デプロイ : Cloudflare Pages(無料枠で十分)
監視     : Sentry(無料枠)
```

選定理由: ランニングコストをほぼゼロに抑えつつ、オフライン対応・共有機能・AI生成まで一気通貫で実装できる構成。veai.jp 既存インフラが別スタックの場合はそちらに合わせて調整する。
