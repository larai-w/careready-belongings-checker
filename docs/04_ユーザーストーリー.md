# CareReady ユーザーストーリー

書式: 「**〜として、〜したい。なぜなら〜だから。**」+ 受け入れ条件 + 深掘り検討

登場人物:
- **恵子さん(58)**: 家族介護者。母(要介護3)のショートステイを月2回利用
- **弟・浩さん(54)**: 遠方在住。たまに送迎を代わる
- **田中さん(34)**: ショートステイ施設の生活相談員

---

## Epic 1: 準備する(コア体験)

### US-1.1 チェックしながら準備する 【実装済み・改善対象】
> 家族介護者として、持ち物を1つずつチェックしながら準備したい。なぜなら頭の中だけで管理すると必ず抜けが出るから。

**受け入れ条件**
- [ ] チェック状態が保存され、アプリを閉じても消えない
- [ ] 進捗(12/34)が常に見える
- [ ] 「今回は不要」な物をスキップでき、進捗母数から除外される

**🔍 深掘り検討**
- 現状は localStorage 保存。**スマホのストレージクリアやプライベートブラウズで全消失**する。準備途中でデータが消えるのは本アプリ最悪の体験 → アカウント同期(Phase 1)まではIndexedDB+バックアップ導線で緩和。
- 「不要」ボタンの意味論が曖昧: 「今回だけ不要」なのか「うちの母には永久に不要」なのか。→ **リセット時に不要設定を残すか消すかをユーザーに選ばせる**現仕様(一括で全消し)は再考の余地あり。
- チェックの単位: 「おむつ」1チェックで良いか?「おむつ×20枚」は数えながら入れる → 数量カウンター(タップで+1)の方が現場の動きに合う。

### US-1.2 箱ごとに詰める 【実装済み・改善対象】
> 家族介護者として、どの荷物をどの箱に入れたか記録したい。なぜなら施設から「◯◯はどの箱ですか」と電話が来るし、複数の箱に分けて詰めるから。

**受け入れ条件**
- [ ] アイテムごとに箱を割り当てられる
- [ ] 箱別ビューで「箱1に何が入っているか」を一覧できる

**🔍 深掘り検討**
- 現状の箱名は「箱1〜4」の固定定義(コード内 `CONTAINERS`)。実際は「赤いボストン」「衣装ケース(青)」など**家庭ごとに呼び名が違う** → 箱名のユーザー編集機能が必要。
- 箱の割り当ては施設側にも価値がある(荷解き・荷造りの時)→ 共有ビュー(US-3.2)に箱情報を含める。
- 未指定アイテムが箱別ビューで見えない現仕様はバグに近い(詰め忘れの温床)→ **「未指定」セクションを常時表示**すべき。

### US-1.3 帰宅時の逆チェック 【新規・差別化機能】
> 家族介護者として、ステイから帰ってきた時に持って行った物が全部戻ったか確認したい。なぜなら施設での紛失(特に衣類・入れ歯・補聴器)が一番のトラブルだから。

**受け入れ条件**
- [ ] 「帰宅チェックモード」に切り替えると、行きにチェックした物だけが未チェック状態で並ぶ
- [ ] 戻っていない物を「未返却」として記録・共有できる

**🔍 深掘り検討**
- これは競合の汎用パッキングアプリに存在しない、**介護文脈固有の機能**。マーケティングの目玉になる。
- 「消耗品(おむつ等)は戻らないのが正常」→ アイテムに「消耗品フラグ」が必要。データモデルに影響するのでPhase 1の設計時点で織り込む。
- 未返却リストをそのまま施設への問い合わせメッセージとして出力できれば、電話が苦手な層に刺さる。

## Epic 2: リストを作る

### US-2.1 テンプレートから始める
> 初めてショートステイを利用する家族として、何を持って行けばいいか雛形が欲しい。なぜならゼロから考えられるほどの知識も余裕もないから。

**受け入れ条件**
- [ ] 「ショートステイ(2泊3日)」「入院」「デイサービス」等のテンプレを選ぶだけでリストが作られる
- [ ] テンプレ取込後に自由に追加・削除できる

**🔍 深掘り検討**
- 現状はAPIが返す固定リストのみで、**ユーザーによる追加・編集が一切できない**。「うちの母は◯◯が必須」に応えられないのは致命的 → MVPの最優先追加機能。
- テンプレの質がSEO・口コミの源泉になる。介護職監修を明記できると信頼度が跳ね上がる。

### US-2.2 AIにリストを作ってもらう 【Phase 2】
> 家族介護者として、状況を伝えるだけでリスト草案を作ってほしい。なぜなら「要介護3・冬・3泊4日・おむつ使用」の掛け算を自分で考えるのは大変だから。

**受け入れ条件**
- [ ] 要介護度・日数・季節・特記事項(おむつ/とろみ/認知症等)を入力するとリストが生成される
- [ ] 生成結果は必ず編集可能な草案として提示(自動確定しない)

**🔍 深掘り検討**
- 医療・介護領域なので**断定的な推奨は避け「草案」として出す**。「薬」など生命に関わる項目は固定で必ず含める設計にする。
- Claude API のコストは1生成あたり数円程度 → プレミアム機能に置くか、初回無料+2回目以降有料が妥当。

## Epic 3: 共有する(バイラルの核)

### US-3.1 家族と分担する
> 遠方の弟として、姉が準備したリストの続きを手伝いたい。なぜなら送迎を代わる日は自分が最終確認をするから。

**受け入れ条件**
- [ ] URLを送るだけで同じリストを開ける(相手はインストール・登録不要で閲覧可)
- [ ] 編集にはログインが必要だが、LINEログインで30秒で入れる
- [ ] 誰がチェックしたかが分かる

**🔍 深掘り検討**
- 「閲覧は登録不要」が普及の鍵。登録の壁を共有の受け手側に置くと連鎖が止まる。
- 同時編集の競合: 本格的なリアルタイム同期はPhase 2。MVPでは「最後の書き込みが勝つ+開くたび再取得」で十分(同時編集の頻度は低い)。

### US-3.2 施設に事前共有する
> 施設相談員として、利用前日に家族の準備状況を見たい。なぜなら不足が当日発覚すると家族に取りに帰ってもらうことになるから。

**受け入れ条件**
- [ ] 家族が発行した閲覧リンクで準備状況(進捗・箱割り当て)が見える
- [ ] 施設側から「◯◯もお願いします」と項目追加リクエストができる(Phase 2)

**🔍 深掘り検討**
- 施設側は**業務でLINEの個人アカウントを使えない**ことが多い → 施設向けはメールリンク/PCブラウザ対応が必須。
- 個人情報の扱い: リスト自体に要介護度や医療情報を含めない設計にすれば、閲覧リンクの心理的・法的ハードルが下がる。リンクは有効期限付き+推測不能なトークンに。

### US-3.3 施設が公式テンプレを配る 【B2Bの核・Phase 2-3】
> 施設相談員として、うちの施設のルール(名前記入・持込禁止物)込みの公式リストを家族に配りたい。なぜなら口頭説明と紙のリストでは伝わらず、電話対応が増えるから。

**受け入れ条件**
- [ ] 施設アカウントがテンプレを作成・QRコード/URLで配布できる
- [ ] 家族はワンタップで自分のリストとして取り込める
- [ ] 施設はテンプレの取込数を確認できる

**🔍 深掘り検討**
- **これが収益化の本丸。** 施設1件の導入 = 家族数十〜数百人の獲得チャネル。
- 施設の稟議を通すための材料: 「忘れ物起因の電話・届け直し対応 月◯時間削減」を事例施設で定量化して営業資料にする。

## Epic 4: 続けて使う

### US-4.1 次回のためにリセットする 【実装済み・改善対象】
> 家族介護者として、前回のリストを使い回して次回の準備をしたい。なぜなら毎回ほぼ同じ物を持って行くから。

**🔍 深掘り検討**
- 現状の「一括リセット」は**チェック・不要設定・箱割り当てを全て消す**。しかし箱割り当てと不要設定は次回も使い回したいのが自然 → 「チェックのみリセット」をデフォルトに変更すべき。
- 「前回何を持って行ったか」の履歴が残ると、紛失時の証跡・季節変化の気づきになる(Phase 2)。

### US-4.2 前日に思い出させてほしい 【Phase 2】
> 家族介護者として、ステイ前日に準備状況を通知してほしい。なぜなら日常に追われて準備を忘れるから。

**🔍 深掘り検討**
- ステイ日付の入力が必要になる=初のカレンダー要素。「繰り返し(隔週金曜)」まで対応すると定期利用者に刺さる。
- 通知チャネルはWeb PushよりLINE通知の方がこの層には確実に届く → LINE公式アカウント(マーケ施策)と機能を統合する。

## 優先度マトリクス(MVPスコープの結論)

| 優先度 | ストーリー | 理由 |
|---|---|---|
| P0(MVP必須) | US-2.1 テンプレ+編集 | 「自分のリスト」が作れないと再訪しない |
| P0(MVP必須) | US-3.1 家族共有 | バイラルの核。技術的にも認証と同時に作るのが効率的 |
| P0(MVP必須) | US-1.1改善(同期・数量) | データ消失の根絶 |
| P1 | US-1.3 帰宅逆チェック | 差別化の目玉。データモデルだけ先行設計 |
| P1 | US-3.2 施設への共有 | B2Bへの布石 |
| P2 | US-2.2 AI生成 / US-4.2 通知 / US-3.3 施設テンプレ | 収益化フェーズ |
