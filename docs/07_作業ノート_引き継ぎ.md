## ⚠️ 引き継ぎ時の注意

1. **ローカルフォルダの移動は自由**(CI/CDはGitHub側で完結)。移動後は `backend/.venv` を作り直すこと(パスが焼き込まれるため): `python3 -m venv backend/.venv && backend/.venv/bin/pip install -r backend/infra/requirements.txt pytest moto boto3`
2. **DynamoDBとCognitoはRETAIN**。`cdk destroy` してもデータは残る(=気軽にスタックを作り直してよいが、テーブル名衝突に注意)
3. **sw.jsのキャッシュ**: フロントを変更したら必ず CACHE_NAME をバンプ(現在v5)。忘れると利用者に更新が届かない
4. テスト用テンプレ(ZRNZDT)とパイロットユーザーは本番テーブルに残っている。実運用開始前に整理する
5. **VEAI LAB. 公開サイトの自動デプロイ**: `/Users/irevail8/Documents/veai_ecosystem/veai-jp-web` にドラフトを置かない。同リポは文体・公開形式の読み取りのみ。公開作業は必ず人間の確認後に行う

## 2026-07-15 プロダクト・SEO戦略メモ

### 持ち物コンテンツ

- `data.json` はダミーではなく、全利用者と施設管理画面が参照する製品デフォルト
- 現在の34項目はパイロットで使うが、現場検証前の初期仮説と扱う
- 製品共通は `data.json`、施設固有は施設テンプレート、家族固有は端末の個人カスタマイズとする
- 詳細とアーキテクチャ図は `docs/08_持ち物コンテンツ設計_アーキテクチャ.md`

### SEOと差別化

- 最初のピラーキーワードは「ショートステイ 持ち物」
- 静的な一覧・PDFとは、「施設固有リスト」「帰宅チェック」「毎回再利用」「登録不要・オフライン」で差別化する
- 記事は持ち物を教えるだけでなく、その場で CareReady を開いて準備を始められる導線にする
- 日本語記事は VEAI LAB. の既存トーン（具体的な介護場面、負担の言語化、控えめな製品紹介）に合わせる
- 戦略と未公開初稿は `docs/09_CareReady_SEO記事戦略_ドラフト.md`

### ターゲットの広げ方

- すぐに旅行・子育て・災害持出まで汎用化しない
- 疾患別ではなく「ケアの外出・移動準備」という仕事で対象を定義する
- ショートステイ → デイサービス・通所リハ → 体験入所・施設入所 → 高齢者の入院・転院の順に、同じ体験のテンプレートと記事を広げる
- 新機能は利用者数だけでなく、二回目の利用、施設コード取込、帰宅チェック利用で判定する

### 開発順序の変更

1. 本番アカウントの安全化と実機E2Eを完了する
2. パイロットで持ち物・施設配布フロー・支払意思を検証する
3. SEO記事を情報コンテンツとして整え、検索需要を観察する。一般向けのアプリ起動CTAはまだ置かない
4. 家族が同期・分担を強く求めたら B-4、施設が準備進捗を強く求めたら B-5 を優先する
5. 施設ごとの数量・名称・個別注記が必要と判明したら、施設オーバーライドを拡張する

**B-4/B-5、AI生成、汎用化を先回りで実装しない。次の開発はパイロットとSEO導線のデータで選ぶ。**
